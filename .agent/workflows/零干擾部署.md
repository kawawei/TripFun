# 茂盛環保 ERP 零干擾平滑部署工作流

本工作流專為 **43 測試伺服器（43.103.3.57）** 設計。採用「本地預先編譯 + 生產映像檔高速串流直傳 + 純映像檔秒級重啟」架構，徹底跳過伺服器端耗損 CPU 與記憶體的編譯階段，保障資料庫與檔案數據卷（`backend_storage`）100% 完整無損。

## 步驟 1：確認本地產物與編譯

1. **前端靜態編譯**：
   ```bash
   cd frontend-web && pnpm build
   ```
   > [!IMPORTANT]
   > 必須確認載入 `frontend-web/.env.production`，同源相對路徑設定無誤。

2. **後端二進制編譯**（若後端 Java 代碼有變更）：
   ```bash
   cd backend && ./mvnw clean package -DskipTests
   ```
   產物確認存在於 `backend/target/erp-0.0.1-SNAPSHOT.jar`。

---

## 步驟 2：本地構建原生 Linux/amd64 生產映像檔

在專案根目錄下，構建專用架構映像檔：

```bash
VERSION=$(date +%Y%m%d%H%M%S)

# 構建前端生產映像檔
docker build --platform linux/amd64 -f docker/server/Dockerfile.frontend \
  -t case-ilaji-erp-frontend:latest \
  -t case-ilaji-erp-frontend:$VERSION frontend-web

# 構建後端生產映像檔
docker build --platform linux/amd64 -f docker/server/Dockerfile.backend \
  -t case-ilaji-erp-backend:latest \
  -t case-ilaji-erp-backend:$VERSION backend
```

---

## 步驟 3：高速串流直傳 43 伺服器並載入

使用阿里雲高速通道，將打包映像直接串流寫入 43 主機 Docker 引擎中（不到 15 秒）：

```bash
export SSHPASS="${TEST_SERVER_PASS:?請先設定 TEST_SERVER_PASS 環境變數}"

docker save \
  case-ilaji-erp-frontend:latest \
  case-ilaji-erp-backend:latest | \
  sshpass -e ssh -o StrictHostKeyChecking=no -o PreferredAuthentications=password -o PubkeyAuthentication=no \
  root@43.103.3.57 "docker load"
```

---

## 步驟 4：43 伺服器極速重啟無狀態容器與記錄部署歷程

在伺服器端重啟前後端服務，並自動在伺服器追加一筆部署歷程記錄（PostgreSQL 與 Redis 維持常駐運行，資料卷不受任何影響）：

```bash
export SSHPASS="${TEST_SERVER_PASS:?請先設定 TEST_SERVER_PASS 環境變數}"
COMMIT_HASH=$(git rev-parse --short HEAD)

# 1. 秒級重啟前後端無狀態容器
sshpass -e ssh -o StrictHostKeyChecking=no -o PreferredAuthentications=password -o PubkeyAuthentication=no \
  root@43.103.3.57 "cd /opt/project/case-ilaji-erp/docker/server && docker compose -f compose.yaml -p case-ilaji-erp up -d --force-recreate --no-deps backend frontend-web"

# 2. 自動在伺服器寫入部署日誌
sshpass -e ssh -o StrictHostKeyChecking=no -o PreferredAuthentications=password -o PubkeyAuthentication=no \
  root@43.103.3.57 "echo \"[\$(date '+%Y-%m-%d %H:%M:%S')] [DEPLOY] 成功部署版本 Commit: ${COMMIT_HASH} (Version: ${VERSION})\" >> /opt/project/case-ilaji-erp/deployment.log"
```

---

## 步驟 5：端點健康檢查與驗證

1. **容器狀態驗證**：
   ```bash
   export SSHPASS="${TEST_SERVER_PASS:?請先設定 TEST_SERVER_PASS 環境變數}"

   sshpass -e ssh -o StrictHostKeyChecking=no -o PreferredAuthentications=password -o PubkeyAuthentication=no \
     root@43.103.3.57 "docker ps --filter 'name=ilaji' --format 'table {{.Names}}\t{{.Status}}\t{{.Image}}\t{{.Ports}}'"
   ```
   確認 `case-ilaji-erp-backend` 與 `case-ilaji-erp-frontend-web` 均進入 `Up ... (healthy)` 狀態。

2. **HTTP 端點測試**：
   ```bash
   sshpass -e ssh -o StrictHostKeyChecking=no -o PreferredAuthentications=password -o PubkeyAuthentication=no \
     root@43.103.3.57 "curl -I -s http://127.0.0.1:81 && curl -I -s http://127.0.0.1:8081/actuator/health"
   ```
   確認前端回傳 `HTTP/1.1 200 OK`，後端健康檢查端點正常。

## 步驟 6：Docker 歷史舊映像清理（智慧保留最新 5 版）

清理伺服器上因升級累積的舊映像檔與懸置快取，嚴格保留每個儲存庫最新 5 個版本，避免硬碟空間膨脹：

```bash
export SSHPASS="${TEST_SERVER_PASS:?請先設定 TEST_SERVER_PASS 環境變數}"

sshpass -e ssh -o StrictHostKeyChecking=no -o PreferredAuthentications=password -o PubkeyAuthentication=no \
  root@43.103.3.57 "/opt/scripts/docker-clean-images.sh"
```
